1. The Big Picture

Every request is a browser call to a Flask route in server.py. Routes talk to the database and the cryptography library, then send a JSON or HTML response back.

2. The Routes (what each URL does)

All routes live in server.py. Colored by group. Solid = needs login.

3. How a Message Gets Encrypted (Hybrid Crypto)

PGP here is not the OpenPGP.js format. It's a custom scheme: RSA wraps a one-time AES key, then AES-GCM encrypts the actual message. Same logic in /api/encrypt and /api/decrypt.

4. The Practice Partner Loop (the coolest part)

The server holds its own RSA keypair. You encrypt to the server; the server decrypts, asks an LLM for a reply, then encrypts that reply to your saved public key. Full end-to-end round trip.

5. The Data (what's stored where)

On startup init_db() + init_practice_keys() create tables and generate the server's keypairs once.

Key takeaway: the server is the trusted middleman in a practice sandbox. It holds the practice partner's private key (so it can decrypt what you send) and holds each user's public key (so it can encrypt replies back). That's why this is a learning tool, not a real secrets app - real PGP never lets anyone else hold your private key.
